# umkim-thin 0.3.11

Patch release: the chart-mirror fix, found when upgrading dev-single to catalog
0.1.6 in 0.3.10.

## Fixed

**The chart mirror outgrew the ConfigMap that seeds it.** The mirror is seeded as
one ConfigMap, but nothing ever pruned it:

- `install.sh` packaged each new chart version *next to* every old one, so the
  directory grew by one tarball per chart per release;
- `kubectl apply` stored the whole object in the
  `last-applied-configuration` annotation, doubling the payload against the
  256 KiB annotation cap;
- the console's init container extracted the tar over `/data/chart-mirror`
  without clearing it, so superseded versions accumulated on the PVC too.

After a few chart bumps the install aborted with:

```
The ConfigMap "umkim-thin-mirror" is invalid: metadata.annotations: Too long:
may not be more than 262144 bytes
```

Changes:

- `install.sh` prunes the mirror to what it just packaged plus every version the
  catalog advertises — the upgrade/rollback set `chartRef` resolves — and
  **replaces** the ConfigMap instead of applying over it, so the tar is not
  duplicated into an annotation.
- The console's init container clears `/data/chart-mirror` before extracting, so
  superseded versions no longer accumulate on the PVC (dev-single held 43 files
  where 23 were seeded).
- The Ansible console role replaces the mirror directory instead of merging into
  it, which is what it had been doing under server-side apply.
- `ci/static.sh` fails when the packaged mirror exceeds the ConfigMap budget, so
  the growth cannot come back silently.

## Upgrade notes

- No console behaviour changed; the image is rebuilt to carry the init-container
  fix and catalog 0.1.6.
- Both dev environments are on `0.3.11 / catalog 0.1.6` with the mirror pruned
  (dev-single 23 files, ha-dev 12).
