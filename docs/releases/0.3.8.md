# umkim-thin 0.3.8

External reverse-proxy support: run the platform behind a proxy you already
have, with its own wildcard certificate.

## Added

- **External TLS termination.** `install.sh --external-proxy`
  (`UMKIM_THIN_EXTERNAL_PROXY=true`, Ansible `external_proxy: true`) tells the
  platform that a proxy in front of the cluster holds the certificate.
  - Every route (console, home, portal, LLDAP, invite page, and the catalog
    apps' routes) publishes on Traefik's plain **`web`** entrypoint instead of
    `websecure`, and renders no `tls` block and no `certresolver`.
  - Traefik's `web -> websecure` redirect and the ACME resolver arguments are
    dropped, so nothing tries to issue a certificate and plain HTTP is not
    bounced.
  - URLs the platform prints and stores stay `https://<host>`; the proxy is what
    makes them https.
  - VPN routes are unchanged: they stay on the internal `vpn` entrypoint with
    TLS, because the WireGuard gateway terminates at Traefik inside the cluster.
- **Forwarded-header trust for the proxy.** Traefik is told to accept
  `X-Forwarded-Proto`/`X-Forwarded-For` on `web` and `websecure`
  (`forwardedHeaders.insecure=true`, or the narrower
  `--external-proxy-trusted-ips` / `external_proxy_trusted_ips` allowlist when
  the proxy address is stable). Without this Authelia rejects the forward-auth
  request: *"Target URL ... has an insecure scheme 'http'"*.
- The setting is **sticky across re-runs** like the trusted-access switches: an
  upgrade keeps the mode unless a flag or the environment changes it.
- `umkim-thin config` reports `tls terminated by an external proxy` when on.
- `docs/install.md` documents the mode, an nginx example and the two
  consequences (the `ClientIP` trusted bypass sees the proxy, and only a
  controlled proxy should reach `web`).

## Changed

- The identity chart's LLDAP portal Ingress now follows
  `traefik.portalEntrypoint`/`portalTLS` like the Authelia portal instead of
  being `websecure`-only with a separate plain-HTTP variant. That removes
  `templates/lldap-portal-ingress-http.yaml`, whose only purpose was the old
  external-proxy workaround.
- `charts/identity` 0.1.12, `charts/umkim-thin` 0.1.7.

## Fixed

- A stray empty argument in the rendered Traefik `additionalArguments` list when
  ACME was disabled (the block scalar kept a leading blank line).

## Compatibility and upgrade safety

No console state, catalog or chart-value migrations. Routes are re-rendered on
the next install or `app reconcile`; nothing else changes. The default remains
Traefik + ACME, so an existing install that does not set the flag behaves
exactly as before.

Single node:

```bash
git fetch --tags
git checkout v0.3.8
git submodule update --init --recursive
sudo ./install.sh --reuse-k3s
# behind your proxy:
sudo ./install.sh --reuse-k3s --external-proxy
```

Provisioned/HA cluster (on the jumphost, prefix with `CI_ON_JUMP=1`):

```bash
git fetch --tags
git checkout v0.3.8
git submodule update --init --recursive
# set external_proxy=true (and optionally external_proxy_trusted_ips) in the env
PROVISION_ENV=deploy/provision-ha.env ./deploy/provision.sh
```

## Verification

- Tier 1: `ci/static.sh` — new assertions cover the identity portal in both
  modes and the console/home/invite Ingresses with `externalProxy=true`
  (no certresolver, no TLS annotation, `web` entrypoint). `ci/novice-test.sh`
  renders `--external-proxy` and checks the config.env, identity values, console
  values and the Traefik arguments.
- Lab (ha-dev, real run): flipped the mode on a live cluster, put an nginx
  container with a `*.ha-dev.umkim.com` wildcard in front on the runner, and
  confirmed over that proxy: portal `200`, console/nextcloud `302` to the https
  portal (no 400, no redirect loop), `POST /api/firstfactor` `200` with a
  session cookie, and authenticated `console`/`home`/`lldap` responses.
  Reverted afterwards; HA is back on Traefik + ACME.

## Fixed

- **Mealie and SparkyFitness postgres could not be upgraded.** Both mounted a
  ReadWriteOnce claim without `strategy: Recreate`, so a rolling update
  scheduled the replacement pod before the old one released the volume; it sat
  in `FailedAttachVolume` until the `--atomic` deadline rolled the release back.
  They now use `Recreate` like every other app chart.
- `ci/static.sh` fails if an app Deployment that mounts a PVC loses
  `strategy: Recreate`, so this cannot regress silently.

## Not taken

- **Sonarr 5.0.0** — pre-releases only; stays on 4.0.20.
- **Prowlarr 3.0.x** — nightly/develop only; stays on 2.7.0.5723.
