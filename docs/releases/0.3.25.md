# umkim-thin 0.3.25

Patch release: two defects found while getting the Miniflux gate green.

## Fixed

**A second invitation sharing an email address failed with a raw database error.**
`Directory.Redeem` checked for an existing *username* but not for an existing
*email*, and LLDAP enforces uniqueness on the lowercased address. The invitee saw

```
creating the account: Database error: Execution Error: error returned from
database: (code: 2067) UNIQUE constraint failed: users.lowercase_email
```

Redeem now looks the address up first and answers in a sentence:

```
email "x@y" is already used by the account "z"; use a distinct address
```

The lookup compares case-insensitively and ignores surrounding space, which is
what LLDAP's constraint does (`sameEmail`, with a table test).

**A freshly invited user could fail their first portal login.** Redeeming reports
success as soon as the account is written, but an LDAP bind can fail for a moment
afterwards - `LDAP Result Code 49 Invalid Credentials` for an account that exists.
Tests that reused a warm portal session never noticed; a browser that must log in
as the new user sees what looks like a wrong password. `createUser` now has a
companion, `awaitDirectoryLogin`, which polls the portal until the new account
really can sign in, and the Miniflux test uses it.

## Also in this release

The Miniflux OIDC test drives the flow explicitly (portal login, click
"Sign in with Directory", land in the app, assert `/v1/me` answers with a user id)
rather than going through the shared `oidcLogin` helper, whose in-progress
heuristic cannot settle on a login page served at `/oauth2/oidc/redirect`.

## Verified

- `go test ./...` and `ci/static.sh` pass.
- The redemption fix is exercised by `TestSameEmailMatchesTheWayLLDAPDoes`
  (6 cases).
- Paperless's OIDC directory-login test still passes against the same suite,
  confirming the helper changes did not regress an existing app.
