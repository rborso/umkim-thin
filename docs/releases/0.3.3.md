# umkim-thin 0.3.3

Trusted-access defaults and LAN trust. The app charts and catalog versions are
unchanged from 0.3.1.

## Changed

- **VPN trusted access is on by default.** New single-node installs publish the
  same-host VPN route and split-DNS entries for installed apps without an extra
  flag. Turn it off with `install.sh --no-trusted-access` or
  `UMKIM_THIN_TRUSTED_ACCESS_ENABLED=false`.
- **LAN trust is opt-in with `--trust-lan`.** It detects the host's directly
  attached private IPv4 subnets from the connected routes, adds them to
  `UMKIM_THIN_TRUSTED_MANAGEMENT_CIDRS`, and excludes the default gateway. The
  existing explicit flags (`--trusted-management-cidrs`,
  `--no-trusted-management`) still work.
- **Management trusted access now defaults off** in the installer, Ansible and
  the console. It requires CIDRs; enabling it without any is refused by the
  console, so the installer also disables a stale `...=true` with an empty list
  instead of letting every app install fail.
- The Ansible default is now `trusted_access_enabled: true`; the console
  template and the console binary default match it.
- Automatic backups remain opt-in from v0.3.2 (`UMKIM_THIN_BACKUP_INTERVAL=off`).

## Existing installations

Trusted access is sticky: a re-run without a flag keeps the value in
`/etc/umkim-thin/config.env`. To turn it on for an existing install, run:

```bash
sudo ./install.sh --reuse-k3s --trusted-access
# or, to also trust the LAN:
sudo ./install.sh --reuse-k3s --trust-lan
```

Then republish the already-installed app routes (they were created with the old
value):

```bash
for app in actualbudget gitea homebox immich mealie nextcloud paperless servarr sparkyfitness; do
  kubectl -n umkim-thin exec deploy/umkim-thin-console -- \
    /usr/local/bin/umkim-thin app reconcile "$app"
done
```

New app installs pick up the new routes automatically.

The app's own login still applies. OIDC apps (Actual Budget, HomeBox, Immich,
Mealie, Paperless, SparkyFitness) still send you to Authelia as their identity
provider; the trusted path removes the portal forward-auth, not app
authentication.

## Verification

- `go test ./internal/app` covers `TrustedAccessEnabled=true` and
  `TrustedManagementEnabled=false` defaults.
- `ci/static.sh`/`ci/novice-test.sh` render the defaults and exercise
  `--trust-lan` against a fake `ip` (subnet detected, gateway excluded).
- The lab gate still runs with the CI environment's explicit trusted-access
  values; the public Authelia route is unchanged.

## Upgrading

Single node:

```bash
git fetch --tags
git checkout v0.3.3
sudo ./install.sh --reuse-k3s
```

Provisioned/HA cluster (on the jumphost, prefix with `CI_ON_JUMP=1`):

```bash
git fetch --tags
git checkout v0.3.3
PROVISION_ENV=deploy/provision-ha.env ./deploy/provision.sh
```
