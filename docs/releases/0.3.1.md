# umkim-thin 0.3.1

A versioning and console-update release. The app charts and catalog versions are
unchanged from 0.3.0.

## Fixed

- **The platform version is exact.** A git build is a release only when HEAD is
  on a `v*` tag and the tracked tree is clean; otherwise it reports
  `dev+<sha>` and the update check stays off. It no longer claims the previous
  release when built from a commit between tags.
- `install.sh` no longer hard-codes `0.2.0`; it uses the same rule as
  `deploy/provision.sh`. Source tarballs without `.git` read the checked-in
  `VERSION` file; `UMKIM_THIN_VERSION` overrides both for a release build.
- The image built for 0.3.1 therefore reports `0.3.1` in the console and
  `GET /api/version`, instead of the previous tag.

## Console

- A permanent **Platform: check/update** link in the header opens a Platform
  panel. It shows the running version, the last check time, the release link,
  and the exact host-side update commands.
- **Check now** runs the read-only release check immediately
  (`POST /api/version/check`, same-origin).
- The update chip opens the same panel when a newer release is published.
- The console still does not update itself; application upgrades remain under
  **Applications**.

## Verification

- The rebuilt dev-single and ha-dev consoles report
  `{"current":"0.3.1","available":false}` from `GET /api/version`; the stale
  `0.2.0` reading is gone.
- `ci/e2e.sh single --gate-only` and `ci/e2e.sh ha --gate-only`: acceptance gate
  67/67, informational journeys 27 passed / 1 skipped. The console browser test
  opens the Platform panel, checks the host-side instructions and calls
  `POST /api/version/check`.
- `ci/static.sh` passes.

## Upgrading

Single node:

```bash
git pull
sudo ./install.sh --reuse-k3s
```

Provisioned/HA cluster (on the jumphost, prefix with `CI_ON_JUMP=1`):

```bash
git pull
PROVISION_ENV=deploy/provision-ha.env ./deploy/provision.sh
```

The console's Platform panel repeats these commands, and the update check
(`UMKIM_THIN_UPDATE_CHECK`, default on) reports when a newer release exists.
