# umkim-thin 0.2.0

The second tagged release. Everything from 0.1.0 still works; this adds apps, a
household home page, install planning, and same-URL VPN access.

## New

- **Four catalog apps:** Mealie, SparkyFitness, Actual Budget and HomeBox, each
  with a pinned chart, auth wiring and a verification journey.
- **Home page** for directory users (`home.<zone>` by default): installed apps,
  live availability and links, no console access. Set the console chart's
  `homeHost` for a different name.
- **Selective backups:** "Back up now" can be narrowed to chosen apps and
  volumes; the manifest records the scope, and only the selected volumes are
  snapshotted. The console state is always archived whole.
- **Full data backups:** when the storage cannot snapshot (NFS, local-path),
  the schedule can copy the volume contents into a per-volume `.tar.gz`
  (`auto` snapshots where possible and copies the rest; `copy` always copies).
  A short-lived read-only helper pod does the copy, the manifest records the
  checksums, and a volume that would leave less than 2 GiB free is skipped.
- **Automated restore:** `backup restore --data` extracts the recorded volume
  copies into their PVCs (scaling the owning workloads down and back), and
  `--platform` applies the object export server-side. The console's restore
  dialog offers both. See [disaster recovery](../disaster-recovery.md).
- **Platform backup:** a separate archive for the cluster itself — every
  Kubernetes object (including Secrets), the console/host state and the
  identity stack's volumes (LLDAP, Authelia, Traefik ACME) — alongside the
  app-data backup. Restoring it is a documented manual sequence.
- **Selectable backup target:** write archives to the console PVC or to an
  NFS export the installer mounts (`--backup-nfs`), with free space and
  writability shown in the screen. Retention and restores follow the target.
- **Editable backup schedule:** enable or disable automatic backups, set the
  interval and retention, and toggle storage snapshots in the Backups screen.
  It is stored on the console PVC and applies without a restart; the installer
  environment variables are only the initial default.
- **Install planning:** choose a namespace for an ordinary app, override each
  PVC's storage class and size, set container resources, and validate the plan
  before installing (`/api/apps/{name}/plan|validate|storage`).
- **Trusted access:** apps keep their public URL inside the VPN (and optionally
  on a management network) with the app's own login instead of Authelia. Off by
  default; see [WireGuard](../quickstart/05-wireguard.md).
- **`install-single.sh`:** prompted single-node setup that writes the env file,
  runs the preflight, then provisions.
- App language selection (English defaults), chart/application licenses in the
  console, and links to each app's upstream project.

## Upgrading

```bash
git pull
sudo ./install.sh --zone example.com --email you@example.com --reuse-k3s
```

- The installer now copies `/data/identity-apps.yml` off the console PVC before
  upgrading identity, so console-managed OIDC clients survive a re-run.
- If your DNS uses explicit records instead of a wildcard, add `home.<zone>`.
- `home.<zone>` is behind Authelia; trusted access does not cover home or
  console.
- Trusted access, the VPN DNS service and the management bypass are inert until
  you enable them; existing installs keep their current routing.

## WireGuard chart 0.1.5

The VPN DNS pod no longer forwards to a hardcoded resolver. An empty
`vpnDNSUpstream` inherits the pod resolver (the cluster DNS, which forwards to
the node's upstreams); set a comma-separated list to pin resolvers instead.
Existing tunnels keep working. A client created before the VPN DNS service
existed still lists the cluster DNS in its config: public names resolve
normally, but app hosts are not mapped to the gateway. Re-download the client
to get the VPN DNS service (`10.43.200.53`) and the same-URL behavior.

Known limitation: the DNS pod installs `dnsmasq` from Alpine's repositories at
startup, so it needs egress to a package mirror. An air-gapped install needs an
image with `dnsmasq` baked in, set via `vpnDNSImage`.

## WireGuard chart 0.1.6

- The gateway accepts forwarded tunnel traffic (`FORWARD -i wg0`), so traffic
  to pod/service IPs is no longer dropped by Calico's or firewalld's default
  forward policy.
- A same-node Traefik keeps the tunnel source address (`POSTROUTING` RETURN),
  so the `vpn-only` allowlist matches the peer. Before this, the gateway
  masqueraded the request to a node/CNI address and trusted VPN routes answered
  403.
- Clients are refused while the endpoint is unset: the console returns a clear
  error instead of a config without an `Endpoint` line.
- The downloaded file is named from a sanitized client name and served as an
  opaque type, so browsers stop saving it as `name.conf.txt` with spaces.
- `install.sh` gains `--wg-endpoint` (default `wg.<zone>`); the Ansible
  template no longer renders `:51820` for an unset endpoint and no longer
  doubles a port that is already present.

## Compatibility

- Platform and app chart versions move independently of the repository tag;
  `charts/*/Chart.yaml` is the chart version.
- No data migration and no removed API. Console/API additions are additive, so
  an existing console keeps working while the apps and catalog are updated.
- The `--reuse-k3s` flag already existed; the upgrade guide previously omitted
  it.
