# umkim-thin 0.3.14

Patch release: the offline rollback that `docs/versioning-plan.md` promised is now
actually implemented.

## Fixed

**An upgraded app could not be rolled back.** The docs say the mirror keeps "the
previous stable tarball … so an upgrade and a rollback work offline", and that a
static check enforces it. Neither was true:

- both installers packaged only the **checked-out** chart version, so no N-1
  tarball was ever produced;
- the catalog still advertised the whole version history, so the console offered
  rollback targets with no package — selecting one failed with Helm's *"does not
  appear to be a gzipped archive"*;
- the two dev targets disagreed: dev-single had N-1 tarballs left over from an
  older release, ha-dev had none at all.

Changes:

- **`scripts/package-charts.sh`** (new, shared by both installers) packages each
  chart's current version *and* its previous version. The previous version is
  exported from the `charts/apps` submodule history with `git archive` at the
  commit that carried it, then packaged, so it is a real chart rather than a
  hand-copied directory. A chart with no history is skipped; a tree without
  submodule history warns rather than shipping a mirror that claims a rollback it
  cannot serve.
- **The catalog is trimmed to the packaged pair.** `versions[]` now names exactly
  the current and previous version of each chart, so "advertised" means
  "installable".
- **`ci/check-mirror-versions.py`** enforces both, from `ci/static.sh`: it
  packages a candidate mirror, then fails if the catalog advertises anything not
  packaged, or if an app chart has no packaged previous version. Reverting either
  property fails the gate with the specific chart named.
- **`VersionInfo.Stable` no longer claims a version without a package**, so the
  API cannot report a default an install would fail on.

## Size

One version of every chart is ~105 KiB; the current + previous pair is ~263 KiB
of tarballs (~287 KiB as the tar the console mounts), against the 1 MiB ConfigMap
that seeds the mirror. Keeping more than one previous version would need the
mirror moved off the ConfigMap — noted in `docs/versioning-plan.md`.

## Docs

`docs/versioning-plan.md` now describes what ships: the current+previous packaging
step, the size budget, and the check that enforces it. The earlier wording
promised a check that did not exist.

## Verification

- `ci/static.sh` and `go test ./...` pass, including three new tests (only
  packaged versions are offered; `stable` requires a package; an install of an
  unpackaged version is refused with the reason).
- `scripts/package-charts.sh` produces 23 packages (13 current + 10 previous);
  every one renders under `helm template`, and the N-1 charts (gitea 0.1.22,
  mealie 0.1.6, servarr 0.3.6) render.
- Degradation checked: run against a tree with no submodule history it warns and
  packages the current versions only, instead of failing or lying.

## Not included

Wiring `ci/upgrade-check.sh` into the gating runs. It now always finds an N-1
candidate, but the gate composition is a separate change.
