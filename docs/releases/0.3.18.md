# umkim-thin 0.3.18

Patch release: 0.3.17 broke the ha-dev chart mirror. Found verifying the deploy,
not by the gate.

## Fixed

**The pruner was handed a path that only exists on the Ansible controller.**
0.3.17 made both pruners keep the platform-chart versions *this run staged*
instead of every version by chart name, and did it by passing
`playbook_dir/artifacts/chart-mirror` to `prune-chart-mirror.py`. `playbook_dir`
is a controller path: on the target the glob matched nothing, so the keep-set was
just the catalog and the prune deleted `identity-0.1.13` and `umkim-thin-0.1.8`.
ha-dev came up with 21 packages and no identity chart.

- The console role writes the staged names to
  `{{ remote_dir }}/chart-mirror-staged.txt` using `fileglob` on the controller,
  and passes that file.
- `prune-chart-mirror.py` reads a list of names. A missing or empty list now
  leaves the mirror alone; before, an empty keep-set was silently read as "the
  platform charts are not wanted", which is what dropped them.
- `ci/static.sh` asserts both behaviours: the staged set retires a superseded
  platform version, and an unreadable staged list changes nothing.

## Why the gate did not catch it

`ci/static.sh` passed throughout: it exercised the pruner with a *directory* that
existed on the same host, so the controller/target split never appeared. The
static check now drives the real interface (a names file) and covers the
unreadable case. The remaining gap is that only a real provision proves the
remote path, which is why this was found there.

## Verification

- Running the real console role against a staged artifacts dir writes 23 names,
  including identity/umkim-thin/wireguard-gateway, and the prune keeps all 23.
- Missing and empty staged lists both leave a 23-package mirror untouched.
- ha-dev re-provisioned from this commit: mirror 23 packages with the identity
  chart present, console renders its identity chart path, 0 unhealthy pods.
