# umkim-thin 0.3.12

Patch release: two bugs found auditing the dev environments after 0.3.11.

## Fixed

**The console offered chart versions it could not install.** The catalog lists
each chart's history for rollback, but only one version per chart is packaged into
the mirror. The whole list was advertised, so picking an older version made
`chartRef` miss the tarball and hand Helm the chart ref — a GitHub tree URL —
which fails with:

```
Error: file '/tmp/helm/cache/repository/gitea' does not appear to be a
gzipped archive; got 'text/html; charset=utf-8'
```

- `app versions` (and the console's version list) now shows only versions the
  mirror actually carries, with the catalog's stable pointer first.
- Installing or upgrading to a catalogued-but-unpackaged version now fails with
  *"chart version X is catalogued but not packaged in the chart mirror"* instead
  of the Helm archive error.
- `ci/static.sh` asserts the catalog's default version is the one this tree
  packages, which is what `docs/versioning-plan.md` already promised.

**The Ansible console role deleted the rollback tarballs** — a regression in
0.3.11. Fixing the mirror growth with `state: absent` removed every tarball the
catalog still advertised for rollback, so a cluster provisioned that way offered
`gitea 0.1.22` and could not install it. The role now prunes to exactly the
catalog's versions (plus the platform charts the playbook installs), and
`ci/static.sh` fails if it removes the mirror directory again.

## Upgrade notes

- No chart or catalog content changed; this is console code plus the deployment
  role and the static gate.
- Take either fix without the other only knowingly: the runtime filter protects
  the user-facing list, the role change restores the rollback tarballs.

## Gate results

- `ci/static.sh` and `go test ./...` pass, including two new regression tests
  (the offered list drops unpackageable versions; an install of one is refused
  with the right message) and the new static checks.
- **dev-single** (rebuilt and verified live): `app versions gitea` now lists
  `0.1.23` and `0.1.22` only, and `app install gitea --version 0.1.19` fails with
  the not-packaged message. Platform conformance PASSED; acceptance gate
  70 passed, 1 skipped; 0 unhealthy pods.
- **ha-dev**: platform conformance PASS, application gate PASS, 71 expected /
  0 unexpected / 0 flaky, 0 unhealthy pods, 0 non-healthy Longhorn volumes.

## Known gap this exposed

The installers only ever package the **checked-out** chart version, so the
catalog's `versions[]` history has no tarballs and `docs/versioning-plan.md`'s
rollback promise ("keep the previous stable tarball so an upgrade and a rollback
work offline") is not implemented. 0.3.12 makes the console honest about it —
it offers only installable versions — but a real N-1 rollback needs the packaging
step to build the previous version from git history and keep it in the mirror.
That is a design change (and a ConfigMap-budget one), not a patch.
