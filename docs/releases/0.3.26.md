# umkim-thin 0.3.26

Miniflux is removed. Its `/v1/me` API authenticates with an API token or HTTP
Basic and never with the session cookie a browser holds, so the check the catalog
requires - an invited tenant signs in and calls the app's API - cannot be asserted
for it honestly. The alternative was a check that passed for the wrong reason.

- `catalog/miniflux.yaml` deleted; `ci/apps.json` entry removed; the gated
  Miniflux tests removed. The chart is reverted in `umkim-charts` (`a30e007`).
- The catalog stays at 0.1.7: it shipped in 0.3.22 and `ci/static.sh` refuses to
  move it backwards.

## Kept from the attempt

Two real defects the work uncovered are fixed and stay:

- **console** (`0.3.23`): `applyOIDCValues` replaced an app's `oidc` values
  instead of merging them, discarding chart-specific fields. That is what left
  Miniflux's `OAUTH2_REDIRECT_URL` empty and made Authelia reject the authorize
  request with `invalid_request: the 'redirect_uri' parameter is required`.
- **identity** (`0.3.25`): a second invitation sharing an email address failed
  with the raw `UNIQUE constraint failed: users.lowercase_email`; it now names the
  account already using the address.

`createUser` also stops pretending a reused account name succeeded: it deletes
the stale `ci-*` account and invites again, rather than returning a password that
was never set.

## Not claimed

Miniflux's SSO does work - the browser lands on the real `/unread` UI - but
proving it in the gate needs token plumbing, which is a separate change. Nothing
here asserts it.
