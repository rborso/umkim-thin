# umkim-thin 0.3.21

Patch release: the catalog's notion of "tested" now comes from evidence instead
of a typed label.

## The problem

The catalog already had a `verify:` block and refused to publish an entry without
one. It was still a claim nothing checked:

- every entry named a `journeys/*.spec.ts` as *the* verification, and the journeys
  are the **informational** suite - a failure there does not fail the gate;
- four declared checks (`ldap_user_visible`, `public_share_exempt`,
  `oidc_login_redirects_to_provider`, `in_cluster_self_resolution`) appear in
  **no test file at all**;
- `wireguard.yaml` pointed at `tests/playwright/journeys/wireguard.spec.ts`, which
  does not exist.

So "tested" meant "someone typed a file name". Four releases in a row have been
fixes for claims that were not true; this one makes the claim itself verifiable.

## Two categories, both derived

- **auto-tested** - every declared check is carried by a test that runs in the
  gate, so a regression fails CI with no human involved.
- **auto-checked** - a test exists, but it is informational.
- **verified** - a human used the app and logged what they did. Independent of the
  above; an app can be both.
- **untested** - installable, nothing claimed.

Nothing sets these by hand. `umkim-thin catalog verify [--strict]` resolves every
`verify.checks` name against `@check:<name>` tags in the Playwright suites and
prints the derived category. `--strict` fails on an unresolved check, and
`ci/static.sh` runs it.

## What changed

- Checks are carried by tests as `@check:<name>` tags in the title, e.g.
  `test('... signs in (LDAP) @check:ldap_user_visible', ...)`. Greppable, survives
  reordering, visible in the HTML report. Per-app loops expand `${p.app}` so one
  templated tag covers each app it runs for.
- `verify.harness` covers an app with no browser surface (the WireGuard gateway is
  `ci/vpn-check.sh`); its `ok`/`bad` lines carry the same tags. The entry no longer
  names a suite that does not exist.
- `verify.human` records a manual pass: date, **the chart version it covered**,
  who, which targets, and what was actually done. Validation rejects a log with no
  steps, so "logged in" alone cannot earn the badge. A log whose version no longer
  matches `chart.version` is reported as **stale** ("verified on 0.1.9") rather
  than dropped or silently inherited - the behaviour chosen for this field.
- `docs/apps/testing.md` is generated by `ci/gen-app-docs.py`; `static.sh` fails if
  it is out of date, because hand-written coverage docs are what drift first.

## Every declared check was rewritten to a real one

The eleven entries now resolve to tagged tests that exist. The ten app entries got
human logs from the 2026-11-19 pass on both targets; actualbudget and vaultwarden
deliberately have none, because that pass skipped their full flows.

## Verification

- `catalog verify --strict` passes; `go test ./...` covers the derivation, staleness
  and the human-log validation (7 cases plus the category matrix).
- The Playwright suites enumerate the same tests with the tags attached.
- `ci/static.sh` passes, including the two new guards.
