# umkim-thin 0.3.2

A backup-default patch. The app charts and catalog versions are unchanged from
0.3.1.

## Changed

- **Automatic backups are off by default.** A new install starts with the
  schedule unchecked and `UMKIM_THIN_BACKUP_INTERVAL=off` in the console
  environment. Manual **Back up now**, the Backups screen, the CLI
  create/restore commands and the platform backup are unchanged.
- The single-node installer (`install.sh`) and the Ansible console template use
  `off` as the default; `UMKIM_THIN_BACKUP_INTERVAL=24h` (or another duration)
  enables a schedule. The Ansible value is quoted (`"off"`) because unquoted YAML
  `off` is boolean false, and boolean/invalid values now fail safe to off.
- Existing installations keep the schedule saved on the console PVC. To turn an
  existing schedule off: **Backups → uncheck Automatic backups → Save**, or

  ```bash
  kubectl -n umkim-thin exec deploy/umkim-thin-console -- \
    /usr/local/bin/umkim-thin backup schedule --interval off
  ```

## Verification

- `go test ./internal/app` covers the default (`BackupInterval = 0`).
- The console's Backups tab renders the disabled schedule while manual backup
  controls remain available.
- `ci/static.sh` passes.

## Upgrading

Single node:

```bash
git pull
sudo ./install.sh --reuse-k3s
```

Provisioned/HA cluster (on the jumphost, prefix with `CI_ON_JUMP=1`):

```bash
git pull
PROVISION_ENV=deploy/provision-ha.env ./deploy/provision.sh
```
