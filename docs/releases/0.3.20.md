# umkim-thin 0.3.20

Patch release: a platform run left the cluster with the apps' identity wiring
reverted. Found by the ha-dev gate dropping from 79 passed to 58 passed / 21
failed immediately after a provision.

## Fixed

**A provision/Ansible run silently dropped every app's OIDC client and public-path
rule.** Those live in `identity-apps.yml` on the console PVC. The platform
re-installs the identity release from its own base values and cannot see that
file, which is expected - `ReconcileIdentityOverlays` exists to reapply the
console-owned layers afterwards. It returned early unless
`identity-settings.yml` or `identity-certs.yml` existed, so a cluster whose only
console-owned identity state was the app contributions kept the reverted config
until the next console-driven install.

The consequences were user-visible, not cosmetic:

- Nextcloud share links and client endpoints (`/s/`, `/public.php`, `/core/css/`,
  the WOPI discovery path) were challenged by the portal, so a public share
  needed a directory login;
- no OIDC app could complete a login, because its client no longer existed in
  Authelia's configuration.

The guard now counts `identity-apps.yml`. A new test asserts that an apps-only
state directory triggers the reconcile and that an empty one still does nothing;
it fails against the old guard.

## How it was found

The gate on ha-dev passed **79/79** at 18:32, then dropped to **58 passed / 21
failed** at 19:50 after a provision, with every failure being a Nextcloud
public-path or OIDC check. Authelia's live config showed `access_control` with
only the portal rules - no app domains at all - while `identity-apps.yml` on the
PVC held 8 OIDC clients and the Nextcloud public paths. That contrast is the
whole bug.

This is the second defect in this stretch that a provision (rather than the
static gate) exposed; the chart-mirror pruner in 0.3.18 was the first.

## Verification

- `ci/static.sh`, `go build ./...` and `go test ./...` pass.
- The regression test fails on the previous guard with
  `expected a reconcile attempt ... got nil`.
- ha-dev re-provisioned with this fix: the gate is back to 79 passed, and
  Authelia's config carries the app domains and OIDC clients again.
