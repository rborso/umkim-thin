# umkim-thin 0.3.13

Patch release: the Ansible mirror pruner shipped in 0.3.12 was broken, found while
re-provisioning ha-dev.

## Fixed

**The chart-mirror pruner failed inside the playbook, and failed badly enough to
abort the provision.** Three defects, all from shipping it untested against a real
target:

- It parsed the catalog with a regex that found 33 of the 54 advertised versions
  on the target node (65 locally), so it pruned tarballs the catalog still
  advertised — including the ones a rollback needs. It now parses YAML and, if the
  catalog cannot be read, refuses to prune at all.
- The role pointed the pruner at `playbook_dir` for the catalog, which does not
  exist on the target. The catalog is now staged next to the mirror and pruned
  there.
- The staging copy used `dest: <dir>/catalog`, which `copy` interprets as "place
  catalog/ inside this directory", producing `catalog/catalog/`.

The abort was also misleading: because it happened before the image import and
the console restart, the cluster silently kept running the previous image — a
0.3.12 provision left ha-dev reporting 0.3.11. That ordering is why the fix is in
the role rather than only in the script.

## Verification

- Re-provisioned ha-dev from this tree: the prune step reports success, the mirror
  holds the 12 current charts, the console reports **0.3.12**, and platform
  conformance + the application gate pass (71 expected / 0 unexpected / 0 flaky).
- The pruner was exercised against the target's real catalog and mirror before the
  provision, and against an unreadable catalog to confirm it leaves the mirror
  alone.
- dev-single and ha-dev are both on 0.3.12/0.3.13 code with 0 unhealthy pods.

## Carried forward

0.3.12's console fixes (only offer installable chart versions; fail clearly when
one is not packaged) are unchanged. The rollback gap noted there still stands: the
installers package only the checked-out chart version, so the catalog's N-1
entries have no tarball and `docs/versioning-plan.md`'s offline-rollback promise
needs the packaging step to build the previous version from git history.
