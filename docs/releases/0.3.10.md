# umkim-thin 0.3.10

Patch release: the catalog and app-chart work that shipped after `v0.3.9` was
tagged, so both dev environments reach the current charts.

## Catalog releases

### 0.1.4 — the uninstall-keep charts

The uninstall-keep fix is a chart change, so it needs a chart release to reach an
installed cluster (the console only upgrades when the catalog names a different
chart version). Every app chart gets a patch bump:

| app | chart | app | chart |
|---|---|---|---|
| actualbudget | 0.1.3 | nextcloud | 0.1.22 |
| gitea | 0.1.23 | paperless | 0.1.15 |
| homebox | 0.1.2 | servarr | 0.3.5 |
| immich | 0.1.13 | sparkyfitness | 0.1.4 |

### 0.1.5 — servarr 0.3.6 rolls Jellyfin on bind-password rotation

The Jellyfin pod carried a checksum of the rendered LDAP ConfigMap, which
contains only the `${LLDAP_BIND_PASSWORD}` variable *name*, not its value.
Rotating the directory bind password therefore left the pod running with the old
password baked into `LDAP-Auth.xml`, and Jellyfin could not bind. servarr 0.3.6
adds a checksum of the referenced Secret, so a rotation rolls the pod.

### 0.1.6 — servarr 0.3.7 pins tags and verifies the LDAP plugin

- A missing component tag or image now **fails the render** instead of falling
  back to `latest`. Every shipped tag is set, so no existing install changes;
  `lidarr` ships disabled without a tag and never renders until enabled.
- The Jellyfin LDAP plugin zip is downloaded unauthenticated and runs with the
  user's credentials. Its sha256 is pinned in values and verified before
  unpacking; a mismatch is refused. `busybox wget` prints *"TLS certificate
  validation not implemented"*, so this checksum is the only integrity check on
  that download.

## Fixed

- `ci/portal-user.sh` deleted a working account when the login check itself could
  not reach the portal (a 403 from the public address, or 000). It now removes a
  stale account only on a definite 401, so an unpinned runner fails with an
  actionable message instead of destroying the account.

## Added

- `ci/static.sh` renders every app chart and rejects an image with no tag or a
  floating one. The source grep reads text, so it could not see a tag chosen
  inside a template expression — which is how `default "latest"` evaded it.
- `ci/static.sh` fails when a chart template changed without a `Chart.yaml`
  bump, and when `catalog/VERSION` moves backwards. The uninstall-keep fix
  changed 27 templates across all ten charts without moving a version, so no
  cluster would ever have been offered it.

## Backlog triage

The remaining review findings were sorted by whether they can ship in a patch
release (no behaviour, configuration or API break; no chart requiring a value an
existing install does not have). Shipped in catalog 0.1.6:

| Item | Why it is patch-safe |
|---|---|
| servarr component tags no longer fall back to `latest` | A missing tag fails the render instead of silently pulling a floating image. Every shipped tag is set, so no existing install changes. |
| Jellyfin LDAP plugin verified by sha256 | The pinned artifact is unchanged; only a mismatch is refused. |
| `ci/static.sh` renders every chart and rejects an untagged image | Test-only. |

Deferred to a minor release, because each changes behaviour an existing install
depends on:

- **Failing closed when a Secret `lookup` returns empty.** `lookup` cannot tell
  "the Secret is absent" from "the API call failed", so turning a regenerated
  password into a hard failure would break a fresh install and any upgrade
  during an API blip. It needs `.Release.IsUpgrade` plus an explicit override,
  which is a new contract.
- **`hostAliases` lookup fallback for the six charts that lack it** (Gitea,
  Nextcloud, Immich and Paperless already have it; actualbudget, homebox,
  mealie, sparkyfitness, servarr and vaultwarden take the injected value only).
  A chart-side fallback would make a standalone chart install resolve Traefik
  itself, which changes what those charts do outside the console.
- **qBittorrent and *arr credentials rewritten on every pod start.** Making the
  chart seed only when the file is absent changes who owns those credentials
  (chart vs. UI), which operators have already relied on in both directions.
- **Identity chart hardening** (Authelia/LLDAP securityContext and probes, LDAPS
  option, required Valkey password). Adding a required password and enabling
  LDAPS would break installs that do not set them.
- **SEC-016 tooling** (shellcheck, govulncheck, trivy, kube-linter). Safe to add,
  but none is installed in the lab or on this host, so it would land as
  permanently-skipped checks; worth doing when CI grows an image that has them.
- **`serveAPI` split, `install.sh`/Go duplication.** Refactors, no user-visible
  fix; they belong with the work that next touches those files.

## Upgrade notes

- The chart/catalog work is delivered by re-provisioning an existing 0.3.9
  install; no console code changed, so the image is rebuilt only to carry
  catalog 0.1.6.
- The charts only add annotations, a checksum, and render-time validation; an
  app upgrade to the 0.1.4+ chart versions reuses the existing data and
  credentials.
