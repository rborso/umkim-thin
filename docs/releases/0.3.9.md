# umkim-thin 0.3.9

Correctness and durability: uninstall no longer destroys data, installs no
longer mutate (or leak through) the live catalog, and the gates now fail on the
classes of defect that let the November storage fault and the stale catalog go
unnoticed.

## Fixed

- **Uninstall without purge deleted the data.** `helm uninstall` removed every
  chart-rendered PVC (the charts render them inline) and the generated
  credential Secret, and the storage class then reclaimed the bytes — while the
  console offered "Uninstall" vs "Uninstall **and delete its data**". Every app
  PVC and generated Secret now carries `helm.sh/resource-policy: keep`; a
  reinstall adopts the kept objects, keeps the same database password and reads
  the existing data. `purge` still deletes the namespace and everything in it.
  The uninstall response (and the CLI) now names the volumes that were kept.
- **An install could rewrite the live catalog.** `renderValues` rendered the
  entry's nested maps in place, and the store hands out shallow copies, so the
  generated `sso.clientSecret` / `postgres.password` were written into the
  snapshot that `GET /api/catalog` serves, and a second install with different
  options reused the first render. `renderValues` deep-copies the values first.
- **The login limiter trusted a spoofable header.** It bucketed on the first
  `X-Forwarded-For` entry, so a client could pick a fresh bucket per request and
  brute-force the login. It now derives the bucket from the proxy chain (the
  immediate peer must be a proxy address, then the rightmost public hop), and
  the failure map is pruned so many source addresses cannot grow it without
  bound.
- **HA ran without `--request-timeout=1h`.** The flag was nested under the
  optional `secrets-encryption` block in the k3s config template, and HA runs
  with encryption off, so a large volume restore through the API was cut at the
  60-second default. The flag is unconditional again, and the live value is
  asserted.
- **Phantom catalog versions.** `versions[]` listed mealie 0.1.5/0.1.2,
  sparkyfitness 0.1.2, vaultwarden 0.1.1/0.1.0 and wireguard 0.1.2/0.1.1, none
  of which was ever committed to a chart. A fresh install picks one, misses the
  mirror tarball and hands Helm a GitHub tree URL. They are removed.
- **The default backup mode captured nothing on the beginner storage.**
  `snapshot` was the default, so on local-path/NFS the schedule produced a
  metadata-only archive. `auto` (snapshot where possible, file-copy the rest)
  is now the default, and the check fails when an archive carries no data.

## Added

- **Kubelet image GC and eviction thresholds** on both install paths
  (`image-gc-high/low=70/60`, hard/soft eviction, `system-reserved`). The
  defaults let app upgrades keep every layer of every replaced tag: dev-single
  reached 51 GB of containerd images before this was cleaned by hand.
- `ci/uninstall-check.sh single|ha` — writes a marker, uninstalls without purge,
  asserts the claim, the bytes and the generated Secret survived, reinstalls and
  reads the marker again.
- `ci/faults.sh --k3s-restart` / `--k3s-crash` — restarts or `SIGKILL`s the k3s
  service on a live node. That is the failure that faulted the Longhorn volumes
  in November; a VM power-off does not reproduce it. Both scenarios wait for the
  data markers and every replica to rebuild.
- `ci/static.sh` guards: every app PVC and Secret keeps data on uninstall, every
  catalogued version exists in the chart history, the k3s `request-timeout` is
  not conditional, and both install paths set the kubelet thresholds.
- `ci/assert.sh` checks the live apiserver's `--request-timeout`.
- `ci/portal-user.sh` verifies the account can actually log in and removes a
  stale test account that a previous run left with a different password (the
  redemption refuses to take an account over, so this used to surface as a mass
  login failure for the whole run).

## Gate results

- `ci/static.sh` passes, including the four new guards.
- dev-single: `ci/uninstall-check.sh` passes (volume, bytes and Secret kept
  across uninstall and reinstall); `--k3s-restart` and `--k3s-crash` pass with
  the data markers intact; `ci/backup-check.sh` reports 26 volumes captured as
  file copies under the `auto` default.
- ha-dev: all three servers restart with `--request-timeout=1h`, 0 unhealthy
  pods and 0 non-healthy volumes afterwards.
