# umkim-thin 0.3.15

Patch release: a bug in 0.3.14's mirror pruning, found verifying the upgrade on
dev-single.

## Fixed

**`install.sh` could no longer prune a superseded chart tarball.** 0.3.14 replaced
the packaging loop with `scripts/package-charts.sh` and then listed the mirror
directory to decide what to keep — but it listed it *after* packaging, so every
tarball already on disk counted as "just produced". Nothing was ever pruned, and a
stale version (dev-single kept `servarr-0.3.4` alongside the new 0.3.6) stayed in
the mirror indefinitely.

- `install.sh` now snapshots the directory before packaging and keeps only what
  the run added (the current version and its N-1).
- The pruner keeps the platform charts (`identity-*`, `umkim-thin-*`,
  `wireguard-gateway-*`) unconditionally, because they are installed by the
  installer rather than the catalog and are unchanged between most releases — the
  snapshot change would otherwise have pruned them.

Verified on dev-single: the stale `servarr-0.3.4` was removed, the mirror settled
at 23 packages (13 current + 10 previous), and the platform charts survived.

## Note on the version string

While verifying, dev-single briefly reported `dev+539bfe3` because the test
checkout had an uncommitted `install.sh`. That is `build_version` working as
designed — a tree that is not exactly at a tag on a clean checkout must not claim
a release — and it cleared once the checkout matched the tag.
