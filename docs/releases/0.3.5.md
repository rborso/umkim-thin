# umkim-thin 0.3.5

Independent catalog/chart release trains, safer and more flexible backups, and
a dark Authelia login theme with a console control.

## Changed

### Release trains

- **The catalog is now runtime data, not only an image artifact.** The console
  loads the bundled catalog as a fallback and can replace `/data/catalog` with
  a validated `catalog-*.tgz` upload; **Refresh** re-reads it. No console image
  rebuild is needed for a catalog release.
- Catalog releases have their own `catalog/VERSION` (`0.1.0` in this release)
  and are built with `umkim-thin catalog package`.
- Chart versions can declare `minimumUmkimThinVersion` on `chart` or on a
  `versions[]` entry; a release console below it refuses the install before
  Helm runs. A `dev+<sha>` build is allowed.
- The chart release path is documented in `docs/release-trains.md`: immutable
  OCI charts, with the local mirror and `charts/apps` submodule as the
  development/offline fallback. App chart versions are unchanged in 0.3.5.

### Backups

- **Compression presets** `none`, `fastest`, `default` (default) and `best` in
  the Backups screen, CLI and `UMKIM_THIN_BACKUP_COMPRESSION`. They apply to
  the metadata archive and volume copies; the console reports a whole-backup
  size (archive + copies + reported CSI snapshot sizes).
- **Add a backup target from the console.** A new target is a directory below
  the mounted `backupRoot`; the console creates it and performs a
  create/write/sync/remove probe before offering it. The CLI equivalent is
  `backup targets add <name>`.
- The single-node installer mounts `/srv/umkim-thin/backups` at `/backups` and
  configures the SELinux type needed for the host path. HA requires a shared
  NFS/Samba or RWX root; the chart rejects a `hostPath` root when `ha: true`,
  and the console refuses to add a target without a shared root. An existing
  `backup_nfs` is reused as the HA root.

### Authelia login theme

- Authelia login/password-reset/consent pages are **dark by default**
  (`charts/identity` 0.1.11).
- **Access → Login page appearance** selects `dark`, `light`, `grey` or
  `auto`. The choice is stored in the console-owned
  `/data/identity-settings.yml` and applied with a Helm upgrade; sessions stay
  valid in Valkey.
- The setting survives console restarts and platform installs: the console
  reapplies the console-owned identity overlays on startup, and theme,
  certificate and app-OIDC upgrades include each other's values layers.
- Vaultwarden 0.1.2 remains catalogued with `minimumUmkimThinVersion: 0.3.4`.

## Compatibility and upgrade safety from 0.3.4

There are no console state, database or backup-manifest migrations. Existing
backup schedules load with the new optional compression field (default); old
archives are still listed/restored, and new archives are standard gzip.

The upgrade is in-place. Use the installer or Ansible, not a bare Helm upgrade:

- **Single node:** re-running `install.sh` creates the host backup root and
  updates the console SELinux context. This adds a host-backed `/backups`
  mount; skip adding new targets if you do not want that path.
- **HA:** keep a shared `backupRoot` (NFS/Samba/RWX). A hostPath root now fails
  closed, and the console will not add a target without a shared root.
- **Identity:** the identity chart rolls once to 0.1.11 for the theme; Authelia
  sessions survive. The installer cannot see the console PVC, so the console
  restarts and reapplies the saved theme/certificate overlays after the install.
- **Catalog:** `/data/catalog` is optional; absent or invalid, the bundled
  catalog is used. Existing apps and app chart versions are unchanged.

Take a platform backup or VM snapshot first.

## Upgrade

Single node (after the release tag is created):

```bash
git fetch --tags
git checkout v0.3.5
git submodule update --init --recursive
sudo ./install.sh --reuse-k3s
```

Provisioned/HA cluster (on the jumphost, prefix with `CI_ON_JUMP=1`):

```bash
git fetch --tags
git checkout v0.3.5
git submodule update --init --recursive
PROVISION_ENV=deploy/provision-ha.env ./deploy/provision.sh
```
